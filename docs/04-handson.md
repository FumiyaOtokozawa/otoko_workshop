## 進み方（AI はここで4回止まります）

## ステップ4（余裕がある人）：自分用のスラッシュコマンドを作る

`.claude/commands/` に `.md` ファイルを1つ作れば、それがそのまま `/ファイル名` になります。

```bash
cat > .claude/commands/my-check.md <<'CMD'
---
description: 変更した範囲だけテストを流して結果を報告する
allowed-tools: Bash(npm run test:*), Bash(git diff:*), Read
---

git diff --name-only main...HEAD で変更したファイルを確認し、
関係するテストだけを実行して、結果を3行以内で報告してください。
CMD
```

`/clear` してから `/my-check` と打つと使えます。

### ここで気づいてほしいこと

プロンプトは**毎回書くもの**ではなく、**環境に置いておくもの**です。
今日の午前中に何度も打った指示は、`CLAUDE.md` かスラッシュコマンドに移せます。
これが「AI と一緒に開発する」の実体です。

# 今日の要点（振り返り用）

| 学んだこと   | ひとことで                                                         |
| ------------ | ------------------------------------------------------------------ |
| **文脈**     | AI は読んだものしか知らない。だから何を読ませるかを設計する        |
| **検証**     | 「できました」を信じない。テストと `npm run verify` に確かめさせる |
| **粒度**     | 大きく頼むほど失敗する。1タスク＝1セッション＝小さな差分           |
| **計画**     | 実装させる前に計画を読む。実装後に直すより10倍安い                 |
| **仕組み化** | 毎回言っていることは `CLAUDE.md` とスラッシュコマンドに移す        |

## 次に学ぶとよいこと

- **サブエージェント**：調査と実装を別のセッションに分けて、文脈を汚さない
- **hooks**：コミット前に自動で `npm run verify` を走らせるなど、機械的な強制
- **MCP**：社内の Issue トラッカーや DB を AI から参照できるようにする
- **CI との連携**：PR に AI レビューを自動で付ける
