## 1. 役割分担（最低3名）

| 役割                     | 人数                | 当日やること                                                           |
| ------------------------ | ------------------- | ---------------------------------------------------------------------- |
| **講師**                 | 1                   | 座学・デモ・全体進行。ハンズオン中は個別対応をしない（進行に専念する） |
| **メンター**             | 2〜3                | ブレイクアウトで個別対応。参加者5名につき1名                           |
| **タイムキーパー兼記録** | 1（メンター兼任可） | 残り時間のアナウンス、詰まっている人の把握、Q&A の記録                 |

**ハンズオン中の隊形**：メイン会場は「作業ルーム」として開けたまま、
質問がある人だけ**ヘルプ用ブレイクアウトルーム**に移動してもらう方式が最も回ります。
チャットに `#help` と書いてもらい、メンターが呼びに行く運用でも構いません。

**巡回のトリガー**：Anthropic Console（API キー方式の場合）でトークン消費が突出している人は、
高確率で同じところをループしています。声をかける優先度を上げてください。

## 3. 合流ブランチの作り方（最重要）

進行差を吸収する仕掛けです。**これがないと、遅れた人がその後ずっと参加できなくなります。**

```
main
 ├─ step/1-done   … Level 1 終了時点（＝ main と同じ。CLAUDE.md にメモが1行入っているだけ）
 ├─ step/2-done   … Level 2 のバグ修正が入った状態
 ├─ step/3-done   … Level 3 の機能追加（期日）が入った状態
 └─ step/4-done   … Level 4 の見本（★☆☆ の Issue を1つ実装した状態）
```

作り方：**この作業自体を Claude Code にやらせてください。運営側のリハーサルを兼ねられます。**

```bash
git switch -c step/2-done main
claude
# /fix-bug に docs/05-issues.md の BUG-1 の再現手順を貼る
npm run verify
git commit -am "Level 2 の完成形：検索の大文字小文字を区別しないようにする"
git push -u origin step/2-done

git switch -c step/3-done step/2-done
claude
# /plan-feature に docs/05-issues.md の FEAT-1（期日）を貼る → 承認 → 実装
npm run verify
git commit -am "Level 3 の完成形：期日の設定と期限切れ表示"
git push -u origin step/3-done
```

参加者への案内文（そのまま読み上げてください）：

> 時間内に終わらなかった人は、いまの作業をコミットだけしておいて、次のコマンドを打ってください。
> `git stash && git switch -c あなたの名前-l4 step/3-done`
> 完成形から続きを始められます。**遅れではなく設計どおりです。**

## 4. リハーサル（1週間前・所要2時間）

講師とメンター全員で、**参加者と同じ手順を最初から通す**。確認するのは次の3点。

1. `npm run doctor` から Level 5 まで、手順書だけで詰まらずに進めるか
2. Level 2・3 の課題を Claude Code が**素直に解けるか**（解けすぎ／解けなさすぎの調整）
3. 1人あたりのトークン消費（＝コスト見積の実測値）

> Level 3 の課題が5分で終わってしまうようなら、受け入れ条件を1つ増やしてください。
> 逆に AI が迷走するようなら、Issue の「やらないこと」を厚くします。

## 5. トラブル対応（当日に起きること上位10件）

| 症状                                      | 一次対応                                                                                                                    |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `claude` コマンドが見つからない           | `npm install -g @anthropic-ai/claude-code`。それでもだめなら PATH を確認。最終手段は claude.ai の Web 版 Claude Code に退避 |
| API キーが効かない                        | `echo $ANTHROPIC_API_KEY` で空でないか確認。シェルを再起動。`~/.zshrc` に書いたのに反映されない例が多い                     |
| 利用上限に到達した                        | ①合流ブランチで先へ進む ②ペアの環境で続ける ③予備キーを配る。**待たせない**                                                 |
| 許可ダイアログが毎回出て進まない          | `.claude/settings.json` が読まれていない可能性。リポジトリのルートで `claude` を起動しているか確認                          |
| AI が無関係なファイルを大量に読み始める   | `Esc` で中断 → `/clear` → 対象ファイルを明示して指示し直す。**これは良い教材なので全体に共有する**                          |
| AI がテストを削除して「通りました」と言う | 絶好の教材。`CLAUDE.md` に禁止事項として書いてあることを見せ、Level 5 の伏線にする                                          |
| `npm run verify` が format で落ちる       | `npm run format` を実行してからコミット。CI でもここが一番落ちる                                                            |
| ポート 5173 が使用中                      | `npm run dev -- --port 5174`                                                                                                |
| Windows で改行コードの差分が大量に出る    | `git config --global core.autocrlf input`                                                                                   |
| 進捗が明らかに遅い人がいる                | ヘルプルームに呼んで**画面共有させる**。チャットの往復では解決しません                                                      |
