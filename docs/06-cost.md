# 06. 利用形態・コスト・利用上限の運用

> ⚠️ **料金と上限の数値は変わります。** 開催の1週間前に必ず公式情報で確認してください。
>
> - 料金：https://www.anthropic.com/pricing
> - Claude Code のドキュメント：https://docs.claude.com/en/docs/claude-code
>   ここに書いてある金額は **2026年時点の目安・見積もり** であり、確定値ではありません。

---

## 1. 4つの選択肢

|                         | ① 各自が個人契約（Pro/Max）      | ② 会社の API キー（従量課金） | ③ 会社の Team / Enterprise 席 | ④ Claude Code on the web   |
| ----------------------- | -------------------------------- | ----------------------------- | ----------------------------- | -------------------------- |
| 初期コスト              | **参加者が立て替え**（$20〜/人） | 会社のクレジットカードのみ    | 席数ぶんの月額                | 契約プランに依存           |
| 経費精算                | 人数分ぜんぶ発生                 | 不要                          | 不要                          | 不要                       |
| **5時間ごとの利用上限** | **あり**                         | **なし**（従量課金）          | あり                          | あり                       |
| 使用量の可視化          | できない                         | **Console で1人ずつ見える**   | 管理画面で見える              | 見える                     |
| 事前準備の手間          | 参加者に丸投げ（＝脱落する）     | キーを配るだけ                | 招待を送るだけ                | 招待を送るだけ             |
| 当日の逃げ道            | 少ない                           | 上限を上げるだけ              | 席の追加                      | –                          |
| 開催後の後始末          | 各自で解約（放置されがち）       | キーを失効させる              | 席を解約                      | –                          |
| ローカル環境が要るか    | 要る                             | 要る                          | 要る                          | **不要（ブラウザで完結）** |

## 2. 推奨：② 会社の API キー（従量課金）＋ 予備として ④

理由は3つです。

1. **懸念3（初期コスト）と懸念4（5時間制限）を同時に解消できる。**
   従量課金には Pro / Max のような5時間ローリングウィンドウの上限がありません。
   組織単位のレート制限（1分あたりのトークン数など）はありますが、
   15名程度が交代で使う分には、通常ティアで足ります。
   ※開催前に、自社アカウントのレート制限ティアを Console で確認してください。
2. **参加者に金銭的負担も精算作業も発生しない。** 事前準備の脱落ポイントが1つ消えます。
3. **運営が使用量をリアルタイムに見られる。**
   これは会計の話ではなく**進行の話**です。トークン消費が突出している人は、
   ほぼ確実に同じところをループしています。**メンターを投入する判断材料**になります。

### ④ Claude Code on the web を予備として使う

ローカル環境の構築に失敗した人・上限に当たった人の**避難先**として案内できるようにしておきます。
ブラウザだけで動くので、当日「どうしても環境が直らない」人を救えます。
事前に運営側で一度動かして、手順のスクリーンショットを用意しておいてください。

### ① 個人契約を選んではいけない理由

- 事前課金は**必ず脱落者を生みます**（当日「まだ払ってません」が出ます）
- 経費精算が人数分発生します
- 運営が使用量を把握できず、**当日の進行判断ができません**
- 5時間制限に当たった人を救う手段がありません

## 3. コスト見積もり

**目安：1人あたり $10〜30 / 日**（Sonnet 中心、初心者ペース、待ち時間が多い前提）。

15名なら **$150〜450** 程度。予算申請は **$500** を上限として通しておくと安全です。

内訳の考え方：

- 初心者は AI の出力を読む時間が長く、**1日あたりのターン数は 80〜150 程度**に収まります
- Claude Code はプロンプトキャッシュが効くため、会話が長くても入力コストは線形には増えません
- **Opus を使うと数倍**になります。だから `.claude/settings.json` で Sonnet に固定しています

> **必ずリハーサルで実測してください。** 講師1名が参加者と同じ手順を通したときの消費額を
> Console で確認すれば、それが最も正確な見積もりです。
> このリポジトリ用の実測値が出たら、この節に追記してください。

### 予算の作り方（Anthropic Console）

1. Console でワークスペースを作る（例：`workshop-2026-xx`）
2. そのワークスペースに **支出上限（spend limit）** を設定する（例：$500）
3. ワークスペース内で**参加者ごとに API キーを発行**する（キー名は参加者の名前にする）
4. 開催後、**すべてのキーを失効させる**

> 参加者ごとにキーを分けるのが重要です。まとめて1本にすると、
> 使用量が誰のものか分からず、進行判断にも後始末にも使えません。

## 4. Pro / Max プランで開催する場合の5時間制限の運用

会社の方針で ① や ③ を選ぶ場合、5時間の利用上限が効いてきます。運用でかわします。

### 仕組み（2026年時点の理解）

- 上限は **5時間のローリングウィンドウ**で管理される
- ウィンドウは**その日の最初のメッセージを送った時点**から始まり、5時間後にリセットされる
- 消費量はモデル（Opus > Sonnet）と**会話の長さ**に比例する
- 週単位の上限も別に存在する

### 打ち手1：初回打鍵の時刻を全員そろえる 〔いちばん効きます〕

Level 1 の開始時に、講師が号令をかけて**全員一斉に最初のメッセージを送らせます**。

```
10:45 一斉スタート  →  15:45 に全員リセット
```

これで運営が**リセット時刻を読めるようになります**。
バラバラに始めると誰がいつリセットされるか分からず、当日の判断ができません。

### 打ち手2：重い作業を新しいウィンドウに置く

タイムテーブルは 15:45 のリセット直後に **Level 5 と PR 作成**が来るように組んであります。
1日の後半で「もう打てません」が起きるのを避けるためです。

### 打ち手3：昼休みにウィンドウを食わせる

10:45 開始なら、12:00〜13:00 の1時間はウィンドウ内にありながら消費ゼロです。
実質の作業時間は4時間に収まります。
**昼休み中は Claude Code を触らないよう、明示的に案内してください。**

### 打ち手4：モデルを Sonnet に固定する

`.claude/settings.json` に設定済みです（参加者の操作は不要）。

```json
{ "model": "sonnet" }
```

### 打ち手5：`/clear` を徹底する

長い会話は毎ターン履歴を送り直すため、消費が増えて速度も落ちます。
ハンドアウトでは **Level が変わるたびに `/clear`** を指示しています。
巡回時に「朝からずっと同じセッション」の人がいたら、その場で `/clear` させてください。

### 上限に到達した人への対応（この順番で）

1. **合流ブランチに切り替えて先へ進ませる** — 待たせない。これが最優先
2. **ペアの環境で続きをやらせる** — 2人1台で、操作を交代する
3. **予備の API キーを渡す** — 運営が2〜3本用意しておく
4. **Claude Code on the web に避難させる**

> 上限に当たること自体は失敗ではありません。
> 「上限に当たったらどう立ち回るか」を見せるのも、この日の学びのひとつです。
