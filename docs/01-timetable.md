## 各コマの台本

### 10:00–10:15 オープニング

伝えることは4つだけ。

1. **今日のゴール**：「機能を1つ追加した PR を1本出す」。ここまで行けば成功。
2. **今日の主題**：「プロンプトのコツ」ではなく「文脈・検証・粒度」。
3. **終わらなくていい**：各コマの終了時刻が来たら、完成していなくても**合流ブランチ**に切り替えて次へ進む。
   > 「今日は全員が同じ場所にいるように設計してあります。遅れても置いていかれません。」
4. **AI が動いている間は"読む"時間**：観察カードを配る。

> 最初に「終わらなくていい」と宣言しておくと、後半で焦って質問できなくなる人が激減します。

### 10:15–10:45 座学①＋ライブデモ（講師が手を動かす）

**話す内容（15分）**

- プロンプトエンジニアリングは入り口。実務で効くのは次の3つ。
  - **文脈**：AI は「読んだものしか知らない」。だから `CLAUDE.md`・ファイル指定・受け入れ条件が効く。
  - **検証**：AI に採点基準を渡す。このリポジトリでは `npm run verify` がそれ。
  - **粒度**：大きく頼むほど失敗する。1タスク＝1セッション＝小さな差分。
- コンテキストは有限。会話が長くなるほど遅く・雑になる → `/clear` を挟む。
- 許可の話：AI はファイルを読み・書き・コマンドを実行する。**何を許すかは自分が決める**（`.claude/settings.json`）。

**ライブデモ（15分）**

同じ依頼を2回、条件を変えて見せるのが最も効きます。

1. 悪い例：`/clear` せず、`「検索がうまく動いてない。直して」` とだけ投げる → 迷走するのを見せる
2. 良い例：`/clear` → `/fix-bug` に**再現手順を貼って**投げる → テストを書いてから直すのを見せる

> デモは Level 2 で参加者がやる課題と**別のバグ**を使ってください（答えを見せてしまわないため、
> 「空白だけのタイトルでタスクが作れてしまう」バグ（BUG-2）をデモに、
> 「検索の大文字小文字」バグ（BUG-1）を参加者用に、と分けています）。

### 10:45–11:15 Level 1「聞く」

**開始時に必ず全員で声を合わせる。**

> 「では 10:45 ちょうどに、全員で最初のメッセージを送ります。せーの。」

これで5時間ウィンドウの開始が揃い、15:45 に全員リセットされます（Pro / Max 利用時）。

- 参加者は `claude` を起動 →`/explain` と打つだけ。
- 出力を読みながら観察カードの「AI は何を読んだか」を埋める。
- **コードは1行も変えさせない**。ここで変更が入ったら止めて `git restore .`。

### 11:15–11:25 共有

2名を指名して、観察カードを読み上げてもらう。

聞き出したいのは**「AI が読んだファイルの違い」**です。同じ `/explain` でも読むファイルは人によって違います。
そこから「同じプロンプトでも文脈が違えば結果が違う」に接続します。

### 11:25–12:00 Level 2「直す」

- `/clear` → `/fix-bug` ＋ Issue の再現手順を貼る。
- **チェックポイント**：AI が「まず失敗するテストを書く」ところまで行ったか。
  ここを飛ばして実装を始めたら、`「先に失敗するテストを書いてください」` と言い直させる。
- 11:55 になったら、終わっていなくても `npm run verify` の結果を確認して締める。

### 12:00–13:00 昼休み

> 「昼休み中は Claude Code を触らないでください。利用枠を無駄に消費します。」

（API キー方式ならこの制約は不要ですが、休憩の質のためにも同じ案内で構いません。）

### 13:00–13:15 座学②「計画させてから作らせる」

- **受け入れ条件**の書き方：「〜できる」形式。**画面を触って確認できる粒度**で3〜5個。
- 悪い受け入れ条件：「期日機能を追加する」 → 何ができれば完成か分からない。
- 良い受け入れ条件：「期日を設定できる」「期日を過ぎたタスクが赤く表示される」「期日なしのタスクも今までどおり追加できる」。
- Plan mode（`/plan-feature` または Shift+Tab で Plan mode に入る）で、**実装前に計画を読む**。
  > 「ここが今日いちばん大事です。計画を読んで違和感があれば、実装前に直せます。実装後に直すより10倍安い。」

### 13:15–14:15 Level 3「作る」

- 全員同じ Issue（★☆☆ の #1「期日」）。
- 手順は [docs/04-handson.md](04-handson.md) の Level 3 のとおり。
- **14:00 アナウンス**：「あと15分です。実装が終わっていない人は、いま `npm run verify` を回してください。
  15分後に終わらなければ `step/3-done` に合流します」
- 14:15 で締める。終わらなかった人は合流ブランチへ。

### 14:15–14:30 相互デモ（ブレイクアウト3人組）

1人1分。画面を共有して「動くところ」だけ見せる。感想戦は不要。
**目的は達成感の共有**です。ここで一度盛り上げると午後後半の集中が戻ります。

### 14:30–15:25 Level 4「任せる」

- Issue カタログから**自分で1つ選ぶ**。★の数で選択を助ける。
- ここで初めて**プロンプトを自分で書く**。テンプレは配らない。
- 早く終わった人は、他の人の PR をレビューする係に回す。
- 15:20 アナウンス：「終わっていなくても、いったんコミットしてください。未完成でも構いません」

### 15:35–16:05 Level 5「仕組み化」

- 観察カードを見返し、**「AI に毎回言っていること」を1つ選んで `CLAUDE.md` に1行足す**。
- 余裕がある人は `.claude/commands/` に自分用のコマンドを1本作る。
- 効果確認：`/clear` してから同じ依頼をもう一度投げ、挙動が変わるかを見る。
  > 「これが"環境を育てる"ということです。今日いちばん持ち帰ってほしいのはここです。」

### 16:05–16:35 PR 作成と相互レビュー

1. `/self-review` で AI に自分の差分をレビューさせる → 指摘を1つでも直す
2. PR を作成（テンプレートが自動で入る）
3. CI が回るのを見る
4. 隣の人の PR を1本レビューする（コメント1件でよい）

### 16:35–17:00 振り返り

問いは3つ。チャットに書かせてから2〜3名に話してもらう。

1. AI の出力で「そのままでは使えなかった」ものは何でしたか？
2. 今日いちばん効いた入力は何でしたか（プロンプトの言い回し／ファイル指定／受け入れ条件／CLAUDE.md）？
3. 明日、自分の仕事のどこで使いますか？

最後に「次に学ぶこと」を紹介して終わる：サブエージェント、hooks、MCP、GitHub Actions との連携。
